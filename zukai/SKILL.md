# zukai — 答えを1枚の図解HTMLにする

長い文章のままだと読まれない。**構造を見つけて、型に流し込む**ためのスキル。

## 使うタイミング
- 直前のAIの回答が長い／読み返す気になれない
- 手順・比較・仕組みを人に説明したい
- 資料として残したい・そのまま見せたい

## 絶対に守ること

1. 🔴 **文章をそのままHTMLに貼らない。** 段落を`<p>`に置き換えただけのものは図解ではない。
   まず「この内容は5つの型のどれか」を決めてから書く
2. 🔴 **器（`template.html`）のCSSは触らない。** `<body>` の「ここから下を差し替える」以降だけ書き換える。
   色・余白・角丸は必ず `var(--...)` 経由で使う（直接 `#fff` などと書かない）
3. 🔴 **使う型は1〜3個まで。** 全部の型を並べると、ただの長いページに戻る
4. 🔴 **元の内容にないことを足さない。** 図解のために数字や手順を創作しない。
   足りない情報があるときは、図解の前に質問する

## 型の選び方

| 内容 | 使う型 | クラス |
|---|---|---|
| やること・順番がある | 手順 | `.zk-steps` |
| 入口→処理→出口がある | 流れ | `.zk-flow`（要点の箱にだけ `is-key`） |
| 良し悪し・前後がある | 比較 | `.zk-compare` |
| 項目 × 観点で並ぶ | 表 | `.zk-table`（`.zk-scroll` で包む） |
| 効果が数字で言える | 数字 | `.zk-kv` |

判断に迷ったら**手順**。ほとんどの説明は順番に直せる。

## 手順

1. 元の内容から**結論を1文**で抜く → `.subhead` に置く
2. 上の表で型を1〜3個選ぶ
3. `template.html` をコピーして `〈題材〉.html` を作る
4. `<body>` 内の `〈…〉` を差し替える。**使わない型の `<section>` はまるごと消す**
5. 見出し（`.headline`）は体言止めにせず、短い文にする
6. ブラウザで開いて確認する。**ダークとライトの両方**をテーマ3択で切り替えて見る
7. 保存先とファイル名をユーザーに伝える

## やりがちな失敗

- **1画面に詰め込む** → 型を減らす。1枚1テーマ
- **箱に長文を入れる** → 箱の中は1行。詳しくは `.zk-node-d` `.zk-step-d` に1文だけ
- **`is-key` を複数の箱に付ける** → 強調が消える。1つだけ
- **テーマ3択を消す** → 消さない。相手の環境がダークかライトか分からない
- **表を横に伸ばす** → `.zk-scroll` で包む。ページごと横に伸ばさない
